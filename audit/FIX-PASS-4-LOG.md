# FIX PASS 4 - accuracy and reliability (2026-09-29)

Baseline before any change: `node --test test/*.test.js` 601 pass / 0 fail;
`node dev/corpus-audit.mjs` recall 94.80%, extras 5.06% (n=1000, seed 3).

One line per item: root cause -> fix -> test name.

- **P0-1 (D1) grouped PDF descriptions** - root cause: `extractGroupedRows` took every character before the amount as an inline description, so the field label `Amount:` became the description AND, being truthy, flipped `claimTrailing`, eating the next transaction's merchant line as this row's `type`; a second line, `Balance as of page 1: SGD 9500.00 Page 1 of 3`, escaped `NON_TRANSACTION_LINE_RE` because the page footer was only matched when anchored at the start of the line. Fix: new shared `stripTrailingFieldLabel()` in `src/core/pdf.js` drops a trailing `word:` token before the amount (and `claimTrailing` is computed from the cleaned fragment), and `NON_TRANSACTION_LINE_RE` now matches `Page N of M` anywhere on a line. `worstcase_grouped_3line.pdf` goes from 0/32 to 32/32 exact descriptions, no `Amount:`, no borrowed merchant, no footer text in `type`. Test: `PASS-4 D1: worstcase_grouped_3line descriptions are merchants, with no field label, no borrowed merchant and no page footer` (`test/ocr-generalisation.test.js`).
- **P0-2 (D2) every data row marked a footer** - root cause: `suggestFooterRows`' `looksLikeFooter` compared a row's filled-cell count against the HEADER's width (`filled <= headerWidth - 2`), so a 12-column real bank export whose ordinary rows fill 5-6 cells tripped on every row and the bottom-up scan consumed the whole table (5/5 here, 205/205 on a real file, exporting zero rows). Fix: in `src/core/suggest.js`, a row carrying both a readable date and a readable amount (`isDateLike` + `isAmountLike`) is a transaction and returns false before the width heuristic runs. `meridian_savings_real_export.csv` now flags 0 footer rows; the `Total,253.55,5200.00,` footer on `meridian_savings.csv` is still caught. Test: `PASS-4 D2: suggestFooterRows finds no footer in a wide real-bank export whose rows all have a date and an amount` (`test/suggest.test.js`).
- **P0-3 (D3) date format guessed from column 0** - root cause: wizard fed `suggestDateFormat` the grid's first column rather than the mapped date column. Fix: `suggestDateFormatForMapping(rawMapping, sampleRows)` in `src/ui/wizard.js`. Test in `test/wizard.test.js`.
- **P0-4 OCR misreads reached export unflagged** - fixes: `isKnownCurrencyCode` (ISO 4217 list) in `src/core/currency.js` so "LTD"/"CIT" fall back to the statement currency with an `unknown_currency` flag; `tagBalanceMismatches` in `src/core/checks.js` flags the row where the printed running balance stops adding up (`balance_mismatch`); amounts under `OCR_AMOUNT_CONFIDENCE_FLOOR` (40) flagged on their own. Tests in `test/currency.test.js`, `test/checks.test.js`.
- **P1-a description tie** - `suggest.js` header tie-break: a column drawn from a tiny value set (DEBIT/CREDIT) loses to a high-cardinality text column. Test in `test/suggest.test.js`.
- **P1-b focus Done silent no-op** - `closeConfirmFocus` now stays on the date screen and says "DD/MM/YYYY reads 0 of 12 dates. Try MM/DD/YYYY, which reads 12 of 12." via new `bestDateFormat()` (`src/core/suggest.js`). Test: `PASS-4 P1-b`.
- **P1-c day<=12 everywhere** - confirm A shows "These dates could be day-first or month-first. We read them as day/month/year. Read them as month/day/year instead" (one click swaps, Yes stays enabled) via `isDayMonthAmbiguous()`. Test: `PASS-4 P1-c`.
