# Export builder + duplicate decisions (2026-10-08, from Nate's cold run with several CSVs)

## Part 1: duplicates and CSV flags (owner: agent A)
Observed: dropping several CSVs raised many "Possible duplicate" cards, each showing ONE row in isolation. The user cannot decide without seeing the other row. Also: a CSV is authoritative; it must be transcribed 100% and never carry "unclear" style flags.

Rules:
1. CSV/XLSX rows never get confidence-style flags: no sign_unclear, low_confidence_ocr, no_decimal, amount_alt, balance_mismatch, unknown_currency (fall back silently to statement currency is fine, but no card). The only flags a CSV row may carry: unreadable date/amount (true failure) and possible_duplicate. Implement in the shared flag producer (normalize.js / checks.js / pipeline.js) keyed on source kind, with a unit test per suppressed flag.
2. Within ONE file, identical rows are real repeats (two coffees, same day): never flag possible_duplicate within a single CSV/XLSX file. (normalize.js line ~272: restrict to PDF/OCR sources, or remove; test.)
3. Across files, a row whose fingerprint matches a row in another file is a true decision. Today mergeAcrossFiles auto-merges those; keep auto-merge ONLY when the two files are the same statement type AND the date ranges overlap (a re-download of the same month). Otherwise raise ONE decision card per PAIR, not per row.
4. The duplicate decision card shows BOTH rows side by side (date, description, amount, currency, which file each came from, and the page snippet for a PDF row), with two buttons: "Keep both" (they are different transactions) and "Keep one" (merge; keep the CSV/text row over OCR). Default focus on "Keep both" for CSV+CSV pairs and "Keep one" for PDF+CSV pairs. One decision resolves both rows. Add FLAG_LABELS copy: "Looks like the same transaction in two files".
5. Verification: a new e2e scenario `dups` in dev/e2e-extension.mjs: drop meridian_savings.csv and meridian_savings_40rows.csv (overlapping rows), assert no per-row duplicate cards, assert the pair card shows two rows with both file names, click Keep one, assert the row count drops by the pair count; then a second run with two different-type CSVs sharing an amount+description on the same date, assert "Keep both" leaves the count unchanged. ## Part 2: the export builder (owner: agent B)
Observed: "Adjust what's exported" is small text; it opens a wall of options (When, What to copy, Columns radio cards with truncated column lists, Customise, pills that will not drag, date format, header row, source columns, currency). "Everything" does not include every field. No way to add a blank column. Nate's target shape:

    date  payee  amount  currency  plaid_account_id  asset_id  notes
    2026-09-01  BONUS INTEREST (SALARY)  47.66  sgd  <blank>  SC_Rach  <blank>

Rules:
1. On the result card, replace the "Adjust what's exported" text link with a visible secondary button "Edit columns" next to the preview caption, and make the preview table header itself clickable to open the same builder.
2. The builder is ONE panel: "Your columns" as a horizontal ordered list of column cards (header name, one sample value underneath from the first row, a drag handle, an x). Drag to reorder must work with pointer events (pointerdown/move/up on the handle, reorder on crossing the midpoint of a neighbour) and with keyboard (focus a card, Alt+Left/Right moves it). Do not rely on HTML5 dragstart/drop (that is what is broken).
3. Below the list: "Add a column" opens a compact menu listing every field this app can produce (grouped: Core, Statement, Original currency, Source columns from the imported files) plus "Blank column" and "Fixed text" (header + constant value). Each menu entry shows its sample value from the first row. Blank/fixed columns are stored on the preset as { field: 'blank', name } / { field: 'const', name, value }, export as '' / value, and survive save/reload.
4. Click a header name to rename it inline (so "Account" can become "asset_id", "Description" can become "payee"). Header rename persists.
5. "Everything" must include every field AVAILABLE_FIELDS knows (incl. post_date, reference, type, orig_amount, orig_currency, source columns); write a test that asserts the Everything layout equals the full catalog minus blank/const.
